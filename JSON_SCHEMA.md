# JSON Schema Documentation

This file documents the structure and fields of the JSON output generated by LED-ML diagnostics.

## Overview

LED-ML generates JSON files containing comprehensive diagnostic telemetry for language model inference. The schema captures activation patterns, gradient information, and performance metrics across all model layers.

## Root-Level Fields

These fields appear at the top level of every LED-ML diagnostic JSON file:

| Field | Type | Description |
|-------|------|-------------|
| `prompt` | String | Raw text input evaluation sequence context. |
| `model` | String | Target architecture name (e.g., `Mistral-7B`, `Qwen/Qwen2.5-7B`). |
| `torch_dtype` | String | PyTorch data type (e.g., `torch.float16`, `torch.float32`). |
| `mode` | String | Tracking environment functional run flags (e.g., `trajectory`). |
| `num_layers` | Integer | Total number of transformer layers in the model ($N$). |
| `ten_pct_cnt` | Integer | 10% baseline token sequence index margin constraint. |
| `response` | String | Generated model output text. |
| `timestamp` | String | ISO 8601 timestamp of diagnostics capture. |

**Example**:
```json
{
  "prompt": "What is the color of chlorophyll?",
  "model": "Qwen/Qwen2.5-7B",
  "torch_dtype": "torch.float16",
  "mode": "trajectory",
  "num_layers": 28,
  "ten_pct_cnt": 36,
  "response": "Chlorophyll is green in color.",
  "timestamp": "2024-08-16T12:34:56Z",
  "0": { ... },
  "1": { ... }
}
```

## Per-Token Structure

For each generated token, LED-ML creates a numbered entry (`"0"`, `"1"`, ..., `"M-1"` for M tokens generated):

| Field | Type | Description |
|-------|------|-------------|
| `{Token ID}/target` | String | Decoded vocabulary target text prediction (the actual word/token). |

**Example** (token 0):
```json
{
  "0": {
    "target": "Chlorophyll",
    "0": { ... },  // Layer 0 data
    "1": { ... },  // Layer 1 data
    ...
    "27": { ... }  // Layer 27 data
  }
}
```

## Per-Layer Structure

Within each token block, there is a nested layer block for each transformer layer (`"0"` to `"N-1"`):

| Field | Type | Description |
|-------|------|-------------|
| `{Layer ID}/hook_overhead_ms` | Float | Live operational layer forward hook execution latency (milliseconds). |
| `{Layer ID}/Forward_Activations` | Dict | Compiled activation mapping metrics and top-K indices. |
| `{Layer ID}/Backward_Grads` | Dict | Compiled Vector-Jacobian Product (VJP) gradient vectors. |

**Example** (Layer 0 of Token 0):
```json
{
  "0": {
    "target": "Chlorophyll",
    "0": {
      "hook_overhead_ms": 2.34,
      "Forward_Activations": { ... },
      "Backward_Grads": { ... }
    }
  }
}
```

## Feature Profile Arrays

Both `Forward_Activations` and `Backward_Grads` contain nested feature profile arrays with the following structure:

| Field | Type | Description |
|-------|------|-------------|
| `map_first_per` | String | Structural token representation tracking array (first window, µ head sampling). ASCII visualization of activation patterns. |
| `map_last_per` | String | Segmented structural tracking matrix array tail signature. ASCII visualization showing tail patterns. |
| `count_first_str` | String | Quantitative metrics tracker index header string. Shows counts for head window. |
| `count_last_str` | String | Quantitative metrics tracker index tail string. Shows counts for tail window. |
| `pct` | Float | Calculated structural density contribution ratio metrics.Percentage of activated neurons and grads. |
| `top_neurons` | JSON String | Serialized data array containing top-K dominant active tracking indices. JSON array of most important neuron indices. |

**Example** (Forward_Activations for Layer 0):
```json
{
  "Forward_Activations": {
    "map_first_per": "░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░",
    "map_last_per": "░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░",
    "count_first_str": "0/358",
    "count_last_str": "0/358",
    "pct": 0.0,
    "top_neurons": "[14, 27, 42, 89, 156]"
  }
}
```

## Hierarchical Summary

```
ROOT (metadata + tokens)
├── prompt: String
├── model: String
├── torch_dtype: String
├── mode: String
├── num_layers: Integer
├── ten_pct_cnt: Integer
├── response: String
├── timestamp: String
└── [Token 0 to M-1]
    ├── target: String
    └── [Layer 0 to N-1]
        ├── hook_overhead_ms: Float
        ├── Forward_Activations
        │   ├── map_first_per: String (ASCII viz)
        │   ├── map_last_per: String (ASCII viz)
        │   ├── count_first_str: String
        │   ├── count_last_str: String
        │   ├── pct: Float
        │   └── top_neurons: JSON String
        └── Backward_Grads
            ├── map_first_per: String (ASCII viz)
            ├── map_last_per: String (ASCII viz)
            ├── count_first_str: String
            ├── count_last_str: String
            ├── pct: Float
            └── top_neurons: JSON String
```

## Field Interpretations

### ASCII Visualization Fields

The `map_first_per` and `map_last_per` fields contain ASCII representations:
- `░` (light shade) — Low/zero activation
- `▒` (medium shade) — Medium activation
- `█` (dark shade) — High activation

These are normalized visualizations of the actual activation/gradient values across neurons.

### Latency Metrics

`hook_overhead_ms` measures the wall-clock time for executing the instrumentation hook on a single forward pass through one layer. This is useful for:
- Profiling diagnostic overhead
- Identifying slow layers
- Comparing performance across models

### Activation Density

`pct` (percentage) represents the proportion of active neurons in the layer:
- `0` = No active neurons (completely inactive layer)
- `1/-1` = All neurons active (fully utilized)

### Top Neurons

`top_neurons` is a JSON-serialized array of neuron indices showing which specific neurons are most active or have highest gradients. Example: `"[14, 27, 42, 89, 156]"` means neurons at indices 14, 27, 42, 89, and 156 are most important for that layer.

## Use Cases

### Memory Analysis

```python
import json

with open("model_diagnostics.json") as f:
    data = json.load(f)

# Calculate total activations across all layers
total_activations = 0
for token_id in data:
    if token_id.isdigit():
        for layer_id in data[token_id]:
            if layer_id.isdigit() and isinstance(data[token_id][layer_id], dict):
                fwd = data[token_id][layer_id].get("Forward_Activations", {})
                if "pct" in fwd:
                    total_activations += fwd["pct"]
```

### Latency Profiling

```python
import json
from collections import defaultdict

with open("model_diagnostics.json") as f:
    data = json.load(f)

layer_latencies = defaultdict(list)

for token_id in data:
    if token_id.isdigit():
        for layer_id in data[token_id]:
            if layer_id.isdigit():
                latency = data[token_id][layer_id].get("hook_overhead_ms", 0)
                layer_latencies[int(layer_id)].append(latency)

# Average latency per layer
for layer_id in sorted(layer_latencies.keys()):
    avg_latency = sum(layer_latencies[layer_id]) / len(layer_latencies[layer_id])
    print(f"Layer {layer_id}: {avg_latency:.2f}ms")
```

### Neuron Importance Analysis

```python
import json

with open("model_diagnostics.json") as f:
    data = json.load(f)

# Find most frequently active neurons across all tokens/layers
neuron_frequency = defaultdict(int)

for token_id in data:
    if token_id.isdigit():
        for layer_id in data[token_id]:
            if layer_id.isdigit():
                grads = data[token_id][layer_id].get("Backward_Grads", {})
                top_neurons = grads.get("top_neurons", "[]")
                neuron_indices = json.loads(top_neurons)
                for neuron_idx in neuron_indices:
                    neuron_frequency[neuron_idx] += 1

# Sort by frequency
sorted_neurons = sorted(neuron_frequency.items(), key=lambda x: x[1], reverse=True)
```

## Notes

- Token IDs are zero-indexed and sequential from 0 to M-1 (total tokens generated minus 1)
- Layer IDs are zero-indexed and sequential from 0 to N-1 (total layers minus 1)
- The `ten_pct_cnt` field is typically 10% of the model's sequence length, used for sampling in visualizations
- All timing measurements are in milliseconds
- Activation percentages are normalized based on +ve, -ve activations/grads
- JSON keys that are numeric (like `"0"`, `"1"`) are kept as strings for JSON compatibility
